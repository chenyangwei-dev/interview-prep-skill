# 可视化 HTML 输出规范

## 默认交付物

生成一个自包含 `.html` 文件并将其作为主要交付物。文件必须能被用户直接双击打开，不需要服务器、构建步骤、包管理器或网络连接。仅当用户明确要求时，才改用 Markdown 或其他格式。

## 信息架构

按以下顺序组织页面；没有适用内容时可合并专项章节，但不可删除证据、缺口、待确认和真实性检查：

1. 报告标题、岗位、生成日期、材料完整性和语言配置。
2. 摘要卡片：强匹配项、部分匹配项、证据缺口、高优先级问题的实际数量。
3. 岗位画像与面试关注点。
4. 岗位—简历匹配矩阵。
5. 核心优势、缺口与风险。
6. 自我介绍与候选人故事库。
7. 核心问题、参考回答、证据、追问和风险。
8. 项目深挖、专业题、行为与压力题。
9. 反向提问、模拟面试和准备计划。
10. 一页速查表、证据账本、术语表和待确认清单。
11. 最终真实性检查。

## 可视化规则

- 用摘要卡片、状态色、标签、表格和分组卡片表达结构；不要用装饰性图表替代证据。
- 只可视化从正文逐项计数得到的数据。没有用户给出的评分口径时，不显示匹配百分比、总分、雷达图或进度环。
- 保持标签语义一致：强匹配使用正向色，部分匹配使用提醒色，无证据或高风险使用风险色，待确认使用中性色。
- 中英文版本可以调整标题宽度和排版，但必须保持相同证据 ID、数字、单位与贡献边界。
- 使用系统字体栈；不要加载外部字体、图标库、CSS 框架或图片。

## 交互规则

最少提供以下交互：

- 章节导航；桌面端保持可见，移动端允许横向滚动或折叠。
- 问题搜索；仅筛选问答卡片，不删除或改写内容。
- 全部展开和全部收起按钮；问答正文使用原生 `details`/`summary`，禁用 JavaScript 时仍可访问。
- 打印按钮与 `@media print` 样式；打印时隐藏导航、搜索和操作按钮，展开完整正文并避免卡片被不合理截断。

交互脚本只操作模板自身的静态元素。不要把用户输入插入 `script`、`style`、`onclick` 或其他事件属性。

## 安全与隐私

- 对公司名、岗位名、简历内容、岗位内容及用户补充执行 HTML 转义。
- 不使用 `innerHTML` 渲染用户内容；搜索和状态更新使用 `textContent`、属性或类名。
- 不包含远程脚本、远程样式、远程图片、分析代码或第三方追踪。
- 岗位来源可以作为普通链接显示，但添加 `rel="noreferrer"`；不要把访问凭据、会话参数或私人链接复制到报告。
- 不输出身份证号、完整住址、私人手机号、私人邮箱或其他与面试准备无关的个人信息。

## 可访问性与响应式

- 使用 `header`、`nav`、`main`、`section`、`table`、`details` 和 `button` 等语义元素。
- 设置正确的 `lang`、UTF-8 编码、viewport、页面标题和清晰的焦点样式。
- 不只依赖颜色表达状态；状态文字必须同时可见。
- 表格放入可横向滚动容器；正文在 320px 宽度下不能发生页面级横向溢出。
- 移动端网格轨道使用 `minmax(0, 1fr)`，网格子项设置 `min-width: 0`；长证据标签允许换行并设置 `overflow-wrap: anywhere`，避免标签撑宽页面。
- 控件必须有可读文本或 `aria-label`，且可通过键盘操作。

## 生成流程

1. 按 `report_language` 复制中文或英文 HTML 模板。
2. 填充报告元数据、摘要计数和所有章节；按内容需要复制卡片、表格行与问答块。
3. 删除未使用的示例块、模板注释和所有 `{{...}}` 占位符。
4. 确认每项主张显示对应标签和证据 ID。
5. 运行 `python scripts/validate_report.py <report.html>`。
6. 若可用，使用浏览器检查 1440px、768px 和 375px 宽度以及打印预览。
7. 在最终回复中提供生成文件的可点击链接，并简要说明报告语言、面试语言和仍待确认的项目数量。

# 缺口突击资料规则

## 目标

将匹配矩阵中的 `无证据` 和高风险 `部分匹配` 转换为短期可执行的学习计划。学习只能提升知识准备度，不能制造简历证据或生产经验。

## 来源优先级

1. 官方产品文档、标准组织、规范、研究论文或项目官方仓库。
2. 官方教程、维护者技术文章或公开课程。
3. 仅在一手来源不足以解释概念时使用高质量二手资料，并明确发布方。

技术问题不要用搜索摘要、聚合站、营销软文或无来源博客作为核心依据。涉及法律、监管、金融合规或安全时，优先当前有效的主管机构、标准组织和原始规范；无法确定适用司法辖区时标记 `[待确认]`。

## 选择与组织

- 只补与 JD 明确要求相连的内容，避免生成泛化课程清单。
- 先处理硬性要求和高概率面试主题，再处理加分项。
- 每个缺口保留 2–4 个能形成学习闭环的链接：概念入口、设计/安全细节、可动手教程或规范。
- 为每个来源分配稳定的 `SRC-xx`，记录标题、发布方、URL、用途和访问日期。
- 外部页面只作为普通链接；可视化 HTML 仍须离线可读，不加载任何远程资产。

## 每个学习单元的必备字段

1. 对应的 JD 证据与简历评级。
2. 优先级和建议时长。
3. 需要理解并能口述的核心概念。
4. 一个可验证产出，例如架构图、threat model、最小实验、评估表、指标树或故障演练。
5. 完成标准：不看资料能解释、设计或演示什么。
6. 面试表达边界：哪些只能称为知识或练习，哪些仍然没有生产证据。

## 时间路径

同时提供：

- 按岗位重要性排序的完整路径。
- 一条 4–8 小时的最短路径；总时长必须等于各时间盒之和。
- 最终综合验收，例如限时白板设计和若干 60–120 秒口头回答。

不要承诺学习时长必然足以掌握主题。时长只是准备建议，使用 `[建议｜依据：…]` 或英文等价标签。

## 真实性边界

- 使用“我没有生产经验；我完成了……练习；我的设计是……”的迁移表达。
- 不使用“我负责过”“我落地过”“我在生产环境使用过”，除非存在 `CV-xx` 或 `USER-xx` 证据。
- 不因阅读文档、运行教程或制作原型而将 `无证据` 改成 `部分匹配` 或 `强匹配`。
- 不把相邻概念混同，例如 model context caching 与 agent memory、普通容器与安全沙箱、通用低延迟后端与量化交易系统。

# 问题与回答框架

## 问题选择

先覆盖高概率、高区分度和高风险问题，再补充通用题。根据职位等级、岗位类型和材料完整度调整数量，不为了达到固定题数添加低价值问题。

建议覆盖：

| 类别 | 关注点 | 默认优先级 |
|---|---|---|
| 自我介绍与动机 | 职业主线、求职动机、岗位理解 | 高 |
| JD 核心能力 | 每项硬性要求及关键软技能 | 高 |
| 项目深挖 | 真实性、个人贡献、决策与结果 | 高 |
| 行为面试 | 冲突、失败、压力、协作、领导力 | 高 |
| 风险问题 | 空档、转型、频繁变动、能力缺口 | 高 |
| 专业或技术题 | 原理、方法、案例、取舍、边界 | 按岗位 |
| 系统设计 | 需求澄清、架构、规模、可靠性、取舍 | 技术岗位高 |
| 管理层面试 | 业务结果、判断、影响力、风险、领导潜力 | 高 |
| 反向提问 | 目标、团队、评价标准、挑战 | 中 |

## 回答结构

### 项目与行为题：STAR-L

1. `Situation`：用一两句话交代真实背景。
2. `Task`：说明个人目标、约束和责任边界。
3. `Action`：重点说明个人采取的行动、判断和取舍。
4. `Result`：给出有依据的结果；没有数字时使用可验证的定性结果。
5. `Learning`：说明复盘、局限及下一次会如何改进。

### 决策与取舍题

使用“目标与约束—备选方案—评价标准—选择—结果—复盘”。不要把事后结果写成当时已经确定的判断。

### 专业知识题

使用“结论—机制—适用条件—边界或反例—与候选人经历的关系”。如果只是知识型回答，明确标记，不假装亲历。

### 系统设计与管理层面试

系统设计使用“澄清—需求与约束—估算—接口与数据—架构与数据流—深挖—质量属性—故障—取舍—演进”。管理层问题使用“结论—证据故事—关键判断—结果—复盘—岗位连接”。生成前读取 [system-and-management-interviews.md](system-and-management-interviews.md)，遵守题目数量、输出字段和经验边界。

### 缺口与风险题

使用“承认事实—解释相关经验—给出补足行动—说明当前状态”。不要回避问题，也不要用无法验证的宏大承诺替代证据。

## 每道核心题的输出字段

```markdown
### Q：问题

- 优先级：高 / 中 / 低
- 类型：可直接练习 / 补充后练习 / 知识型参考
- 面试官意图：[推断｜依据：岗位要求或常见考察点]
- 证据：JD-xx；CV-xx；USER-xx
- 参考回答：第一人称、口语化、60–120 秒
- 连续追问：2–4 个
- 回答风险：[建议｜依据：证据边界]
- 待确认：没有则写“无”
```

字段名称使用 `report_language`，问题、参考回答和连续追问使用 `interview_language`。证据 ID 不翻译。

## 中英文与双语输出

英文回答应按照英文面试的自然表达重新组织，不逐句翻译中文草稿。优先使用短句、明确主语、清晰贡献边界和可口述的过渡；不要添加来源没有支持的商业术语或领导力措辞。

双语模式仅配对自我介绍、核心问题与回答、高风险回答和关键反向提问。使用以下结构：

```markdown
### Q1 — Tell me about yourself / 请介绍一下你自己

**English answer**

...

**中文理解与表达提示**

...

**Evidence / 证据**

CV-01, CV-03
```

让双语版本共享证据与事实边界，不要求句子一一对应。报告的岗位画像、匹配矩阵和准备计划只使用 `report_language`，避免整份文档机械重复。

## 追问设计

优先追问容易暴露真实性和能力边界的内容：

- 你本人具体做了什么？
- 为什么选择这个方案，放弃了什么？
- 指标口径和基线是什么？
- 遇到的最大阻力是什么？
- 如果结果不理想，原因是什么？
- 如果重新做一次，会改变什么？
- 如何证明结果与行动有关？
- 团队成员或利益相关方会如何评价你的贡献？

## 自我介绍

生成 30 秒、90 秒和 3 分钟三个版本。围绕“当前定位—最相关经历—代表性证据—与岗位连接—应聘动机”组织，不逐条朗读简历。

## 反向提问

优先询问岗位成功标准、入职前 90 天目标、当前最大挑战、协作方式、决策机制和评价标准。不要询问职位描述或公司公开页面已经明确回答的问题。

## 质量标准

让答案听起来像候选人本人，而不是统一模板。减少形容词，增加具体行动、约束、取舍和可验证结果。检查英文回答是否自然可说，检查中英文版本是否保持相同证据、数字和贡献边界。若答案异常完整或完美，重新检查是否混入了没有证据的细节。
